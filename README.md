# Motion Studio

Motion Studio is a browser-based webcam motion-capture demo. It tracks a person's face, upper body, and hands with MediaPipe Tasks, then retargets those movements to a Three.js VRM avatar. The camera feed and landmark processing stay in the browser; no video is uploaded by the application.

## Start the application

```sh
npm install
npm run dev
```

Open the Vite URL printed in the terminal, usually `http://localhost:5173`, in Chrome or Edge. Use localhost or an HTTPS address: browsers require a secure context before granting camera access. Allow camera access when prompted.

To make the page available to other people, deploy the built site to an HTTPS host. A QR code opened from `localhost` points back to that same device, so it will not open the local development server on a phone. The QR image is generated by QRServer and encodes the current page address.

Production build and local preview:

```sh
npm run build
npm run preview
```

The preview server prints the address to open. The build output is written to `dist/`.

## Use the studio

1. Choose an avatar from **Avatar Model**. The available VRM files are bundled in `public/`.
2. Select **Enable camera** and grant permission. The app requests a front-facing camera at an ideal 1280 × 720 (16:9, the same shape as the recordings the motion limits were measured from) at 30 fps, with audio disabled.
3. Stand where your face, shoulders, elbows, and hands are visible. Keep signing movements around the chest and upper abdomen for the avatar's tracked arm workspace.
4. Use the small **Live · Landmarks** inset to check what the trackers see. It mirrors the preview for a natural selfie view and draws face, arm, and finger landmarks over the video.
5. Select **Disable camera** to stop the video tracks and end capture.

### Studio controls

| Control | What it does |
| --- | --- |
| Avatar Model | Loads one of the bundled VRM avatars into the stage. |
| Enable camera / Disable camera | Starts or stops the local camera and motion tracking. |
| Reset view (↺) | Resets the Three.js camera and the avatar's normalized humanoid pose. Tracking resumes applying live pose on the next detection frame. |
| Fullscreen (⛶) | Expands the avatar stage to browser fullscreen. Exit with the browser's fullscreen control or Escape. |
| QR thumbnail | Opens a full-screen QR view for the current page. Use **Back to studio** or Escape to return. The studio remains active behind the QR screen. |

The QR service receives the page URL in order to generate the code. The camera stream is separate and is not sent to that service.

### Status indicators

| Indicator | Meaning |
| --- | --- |
| Face: Detected / Waiting | Whether a face landmark set is available. |
| Upper body: Tracking | Both arms have usable wrist coordinates inside the signing workspace. |
| Upper body: Partial | One arm is being tracked; the other uses the arms-at-sides pose. |
| Upper body: Neutral pose / At sides | No usable arm targets are available. The displayed state and fallback pose depend on `neutral.enabled` in `public/constraints.json`. |
| Hands: Detected / Waiting | At least one hand is being tracked by the hand landmarker. Missing hands ease their fingers toward neutral. |
| FPS | Approximate rendered frames per second, measured over the previous second. |
| LIVE TRACKING / LOCAL PROCESSING | Detection is running / the app is waiting for camera input. |

## How the avatar is controlled

The avatar is controlled by three landmark streams. Face landmarks drive the head and selected facial expressions; pose landmarks drive the upper body and arm placement; hand landmarks drive the wrists and finger joints. The app does not map hips or legs. For the detailed retargeting behavior, bone names, smoothing, workspace limits, and fallback rules, see [Avatar control and retargeting](docs/avatar-control.md).

### Current motion limits

- The avatar root stays facing the screen. Head tracking can turn, tilt, and nod the head.
- The torso can lean slightly side to side. Hips and lower-body bones remain fixed; front-to-back torso bending is disabled.
- The allowed wrist and elbow workspaces, joint-angle ranges, smoothing rate limits, torso lean, and fallback pose are controlled by `public/constraints.json`.
- When pose data is missing or a wrist leaves its configured workspace, the affected arm uses the configured neutral pose or the built-in arms-at-sides pose.
- The hand solver drives the wrist and 15 finger joints per hand (three joints for each of thumb, index, middle, ring, and little finger). The bundled VRM hand frames receive a wrist-roll correction so their palms can face the camera.
- Facial expressions are applied only when the selected VRM contains a compatible expression preset. Available mappings include blink, smile/joy, jaw open, and a reduced frown/angry value.

## Tune avatar motion with `public/constraints.json`

This JSON file is loaded at runtime from `/constraints.json`. Edit the values in `public/constraints.json`, save, and reload the app. The same file is copied to `dist/`, so updating a deployed config does not require rebuilding the JavaScript bundle; upload the changed JSON alongside the site. The app falls back to built-in limits if the file cannot be loaded or valid fields are missing.

The `arms.Left` and `arms.Right` blocks set each side's accepted wrist/elbow workspace, upper-arm and elbow rotation ranges, and maximum angular change per second. Coordinates are relative to shoulder center/span, not pixels. `neutral.enabled` selects a configured sign-ready pose when tracking is missing; set it to `false` to use the built-in arms-at-sides fallback. `torsoTilt`, `head.roll`, and `handAssign.maxDistSpan` control torso lean, head roll, and hand-to-arm side matching. Optional `fingers` ranges can clamp individual finger-joint rotation axes; they are omitted by default, so live finger tracking remains unrestricted.

For the full field reference, units, current values, and worked tuning examples, see [Avatar control and retargeting](docs/avatar-control.md#using-publicconstraintsjson).

## Processing and network use

The app uses Vite, TypeScript, Three.js, `@pixiv/three-vrm`, `@mediapipe/tasks-vision`, and Kalidokit. MediaPipe's WASM files are loaded from jsDelivr; the face, pose, and hand model files are loaded from Google Cloud Storage on first camera startup. The app tries the GPU delegate first, then retries with CPU if GPU initialization fails.

Detection runs in VIDEO mode at roughly 30 updates per second when the main thread can keep up. Three.js renders continuously with `requestAnimationFrame`. Detection currently runs on the browser's main thread, so slow model inference can lower rendering responsiveness.

## Troubleshooting

- **The camera prompt does not appear:** open the app on localhost or HTTPS, check the browser's site permissions, and ensure another application is not exclusively using the camera.
- **Motion capture fails while loading models:** check that the browser can reach jsDelivr and Google Cloud Storage. The first model load requires network access. The console reports the stage of startup that failed.
- **The constraints warning says it received HTML instead of JSON:** verify that the file is named `public/constraints.json` and that the running server serves it at `/constraints.json`. Invalid JSON syntax is rejected and the app uses built-in defaults until corrected.
- **One arm stays stuck in a fixed pose while the status says Tracking:** open the Arm HUD. `INFERRED` with `up` pinned at the same value usually means a bad range in `public/constraints.json` (a collapsed `[0,0]` range is now rejected with a console warning, and `npm test` checks the shipped file).
- **The avatar moves weakly or falls back to its neutral pose:** improve lighting, move farther into view, uncover shoulders and hands, and keep wrists inside the workspaces configured in `public/constraints.json`.
- **The QR image is missing:** QR generation uses an external image service; share the page address directly if that service is unavailable.
- **The production build warns about a large JavaScript chunk:** this is currently a size warning from Vite, not a build failure.

## Research evidence

The root `research/` directory is kept as local evidence for future iterations. It is not loaded by the app and is not copied into `dist/`. The current `public/constraints.json` contains the extracted control ranges; use the research evidence to review or improve those values, then update the JSON. See [Avatar control and retargeting](docs/avatar-control.md#research-evidence-and-production-build).

## Setup coach, arm HUD and 3D mode (added in V4)

- **Setup coach** (sidebar): live advice when you are too close/far, shoulders or elbows are out of frame, a hand leaves the picture, light is dim or behind you, the camera gives low resolution, or the app runs slowly. Tips appear only after the problem persists ~1.5 s. The static *Setup tips* list under it has the checklist: stand ~1.5–2 m back, camera at chest-to-eye level, light in front, plain contrasting top, 720p+ webcam.
- **Arm HUD** (top-left of the stage, **D** toggles): per arm `TRACKED / INFERRED / CLAMPED / HELD / NEUTRAL / 3D`, the normalized wrist position (`wx`, `wy` in shoulder spans), upper-arm and elbow angles, and why. If an arm looks wrong, read this first. Hand landmarks in the inset are coloured by the avatar arm they drive: teal = person's Left, orange = Right.
- **3D (beta)** (button `3D` or key **T**, or `?arms=3d`): bone directions from the pose model's world landmarks, hand orientation from a palm frame, finger spread from the landmarks. See [docs/avatar-3d.md](docs/avatar-3d.md). Falls back to the 2D path per arm when elbows are not visible.
- **Performance:** one model runs per frame (round-robin) and bones ease toward targets in real time, so the display stays smooth while tracking updates at its own rate. Open with `?pose=lite` for a lighter pose model.
- **Tests:** `npm test` (3D solver round-trips, constraints validation).

## Avatar rig layer

Rest poses, wrist calibration and per-avatar overrides are configured in `public/avatar-rig.json`; see [docs/avatar-rig.md](docs/avatar-rig.md).

## Rig editor

Press **E** (or the ⚙ button) in the app to open the rig editor: keep arms in front of the body, edit the rest pose, calibrate an avatar, and export `avatar-rig.json`. See `docs/rig-editor.md`.
